## 8. SECURITY GRAPH

### Security Requirements (All Extensions Executing Code/Processing Files)

```
INPUT VALIDATION
    │   - Sanitize all user inputs
    │   - Validate file paths (no traversal)
    │   - Validate command arguments
    ▼
PATH VALIDATION
    │   - Resolve absolute paths
    │   - Check workspace boundaries
    │   - Reject symlinks outside workspace
    ▼
ARGUMENT VALIDATION
    │   - No shell metacharacters
    │   - Use array args, not shell strings
    │   - Allowlist known flags
    ▼
PROCESS LIMITS
    │   - Max concurrent processes: 3
    │   - Max memory per process: 512MB
    │   - Max output size: 10MB
    ▼
TIMEOUT ENFORCEMENT
    │   - Default: 30s (configurable)
    │   - Hard kill on timeout
    ▼
CANCELLATION SUPPORT
    │   - User can cancel anytime
    │   - Clean process tree termination
    ▼
OUTPUT LIMIT
    │   - Truncate at 10MB
    │   - Stream, don't buffer all
    ▼
CLEANUP
    │   - Temp files removed
    │   - Orphan processes reaped
    ▼
SECURITY AUDIT
    │   - Static analysis (ESLint security)
    │   - Dependency scanning
    │   - Secret scanning pre-release
```

### Threat Model

| Threat | Mitigation |
|--------|------------|
| Command injection | Array args, no shell, allowlist |
| Path traversal | `path.resolve()`, workspace check |
| Unbounded processes | Process pool, hard limits |
| Unbounded output | Streaming, size limits |
| Orphan processes | `child_process` tracking, SIGKILL cleanup |
| Secret leakage | No logging of env, args, output |
| Dependency vulns | `npm audit`, pinned versions |
| Code execution | Sandbox where possible |

## 13. RISK ANALYSIS

### High Risk Items

| Risk | Impact | Mitigation |
|------|--------|------------|
| Compiler IR access varies by version | Darshana core feature | Label clearly: ACTUAL/DERIVED/SIMULATED; graceful degradation |
| Debug Adapter Protocol complexity | Avalokana integration | Start with VS Code built-in debug API; add DAP later |
| WASM SQLite performance | Ganitha large DBs | Test early; fallback to native if available |
| AI explanation accuracy | Vyakhyana trust | Mandatory labeling; user consent; validation layer |
| Cross-platform toolchain paths | Vyapaka/Kriyasala | Extensive test matrix; per-platform detection logic |
| Process cleanup on crash | All execution extensions | Process tracker with SIGKILL on extension deactivation |
| Large visualization rendering | Anumana/Rachana/Tantra | Virtualization, canvas/WebGL, pagination |

### Medium Risk Items

| Risk | Impact | Mitigation |
|------|--------|------------|
| VS Code API changes | All extensions | Use stable APIs; version checks; abstraction layer |
| Dependency vulnerabilities | All | `npm audit` in CI; pinned versions; minimal deps |
| Extension host memory | Long-running | Dispose resources; weak refs; periodic cleanup |
| User data migration | Config/schema changes | Versioned config; migration functions; backup |
